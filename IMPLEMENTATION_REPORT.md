# Отчёт: Python Telegram MVP

Дата: 20 октября 2026. Репозиторий: RicoElLong/Bot-tg. База: `c16eeb4`. Рабочая ветка: `feat/python-telegram-mvp`; опубликована в GitHub 20 октября 2026 по разрешению владельца. Основная ветка не изменена.

## Изменения

- Сохранён вход `python bot.py`; исходное приветствие расширено регистрацией и главным меню.
- Добавлены python-telegram-bot 22.8 и SQLite, без дополнительных сервисов и веб-сервера. Зависимости закреплены точными версиями.
- `/start`, `/help`, `/profile`, `/privacy`, `/subscribe`, `/unsubscribe`, `/stop`, `/delete_me`; обработка только личных чатов.
- Отдельное согласие на обработку, затем добровольное рекламное согласие. Для каждого — текст, версия, время UTC, источник. Подписка на бота не является рекламным согласием. Повторная регистрация не создаёт дублей; старые кнопки не восстанавливают отозванную подписку.
- Кнопки «Акции», «Меню», «Доставка», «Контакты». Ссылка акций не выдумана: настраивается владельцем.
- Атрибуция `/start <метка>`, безопасная проверка меток, генерация ссылки для размещения в QR. Генератор изображений QR не добавлен.
- Администраторы определяются исключительно `ADMIN_IDS`. Создание текста/фото, предпросмотр только автору, подтверждение с одноразовым токеном, отмена, статистика и история с результатами по кампаниям, аудит действий.
- SQLite WAL, параметризованные запросы, транзакционное подтверждение и фиксация аудитории, повторная проверка согласия, блокировка второго процесса с той же базой.
- Долговечная очередь и защита от повторных update_id/подтверждений/доставок. `sent` означает приём Telegram, не прочтение. Неопределённые результаты не повторяются автоматически.
- Все исходящие пути проходят Gateway. По умолчанию sandbox: сообщения/фото/предпросмотр только в SQLite. Сеть polling и реальные сообщения требуют независимой ручной активации. Sandbox-базу нельзя переключить в live.
- Обработка429/retry_after с ограниченными повторами, forbidden, bad request, сетевой неопределённости; консервативный глобальный и початовый лимиты. Долгие flood-wait не удерживают общий lock.
- Существующий webhook не удаляется: безопасный PollingBot блокирует стандартный автоматический deleteWebhook библиотеки. Накопленные события не сбрасываются.
- Онлайн backup API SQLite, integrity_check, восстановление исключительно в новый файл, карантин старых очередей. Нативные ACL/шифрование носителя и внешняя копия требуют настройки владельцем.

## Не проверено и требует владельца

1. **Перевыпуск токена**, новый токен только в локальную `.env`; очистка старой Git-истории не выполнялась.
2. Настройка собственного username/ADMIN_IDS, правильной страницы акций и проверка ссылок меню/доставки.
3. Утверждённые документы согласий, версии, сроки хранения/удаления, права на фото и рекламные материалы.
4. Нативная Windows: запуск, Ctrl+C, файловая блокировка msvcrt, ACL и Планировщик. Автотесты запускались на Linux; Windows-ветка не выдаётся за проверенную.
5. Настоящий Telegram: polling, пользовательские кнопки, фото/предпросмотр, одна кампания одному добровольному тестировщику. Ни getMe/getUpdates, ни реальный polling/доставка разработчиком не выполнялись.
6. Самостоятельная защита и перенос копий вне компьютера, расписание и сроки удаления копий; SQLite здесь не зашифрована. Копии могут содержать уже удалённых гостей — после restore нужны повторные удаления/отписки.
7. Ветка опубликована в GitHub по разрешению владельца. Объединение и запуск требуют отдельного согласования. Сайт Rest не опубликован и не изменён.

Эта версия не объединяется автоматически с CRM Node.js/PostgreSQL из Rest. Телефоны/дни рождения/бонусы, веб-админка, планирование кампаний по времени, MAX и Instagram не добавлялись. Для работы500 подписчиков достаточно постоянно работающего компьютера; надёжность зависит от питания/интернета/режима сна и регулярных копий. Telegram не даёт гарантии exactly-once при сетевой неопределённости — такие доставки изолируются, а не повторяются вслепую.
