# Telegram-бот ресторана «Дети лейтенанта Шмидта»

Python 3.12+, python-telegram-bot 22.8, SQLite. Запуск через long polling на Windows: домен, публичный сервер и входящие порты не нужны. Компьютер должен быть включён, подключён к интернету и не уходить в сон.

Этот бот работает в репозитории **Bot-tg** самостоятельно. Сайт Rest и его Node.js/PostgreSQL backend не изменены; синхронизации двух баз клиентов здесь нет. Администрирование выполняется внутри Telegram, отдельной веб-панели у этой Python-версии нет.

## 1. Сначала замените опубликованный токен

В истории репозитория был `.env`. Если в нём находился действующий токен:

1. Откройте **@BotFather**, отправьте `/revoke`, выберите своего бота.
2. Получите новый токен, сохраните его только в локальной `.env` или защищённых переменных окружения.
3. Не отправляйте токен в чат, не вставляйте в команды/скриншоты/GitHub. Удаление `.env` новым коммитом не очищает старую историю, поэтому отзыв токена обязателен.

Новые изменения исключают `.env` из Git. `.env.example` содержит только пустые поля и безопасные настройки. Для удаления секрета из старой истории понадобится отдельная согласованная операция; эта инструкция историю не переписывает.

## 2. Установка на Windows

Установите Python 3.12 или новее с python.org и Git. Откройте PowerShell в папке проекта. Код должен содержать `restaurant_bot/` и `tests/` из ветки `feat/python-telegram-mvp`; исходная `main` с одним приветствием недостаточна. Код опубликован в ветке `feat/python-telegram-mvp`: https://github.com/RicoElLong/Bot-tg/tree/feat/python-telegram-mvp. Слияние с main и запуск не выполнялись.

Если получен архив исходников, распакуйте его в отдельную папку. Для установленной версии:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Не копируйте `.env.example` поверх уже настроенной `.env`. Команды используют Python напрямую, менять ExecutionPolicy и активировать окружение не требуется. На Linux аналогичный интерпретатор — `.venv/bin/python`.

Проверьте код **без токена и интернета Telegram**:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

При `ENABLE_TELEGRAM_POLLING=false` команда `python bot.py` намеренно останавливается до любых сетевых вызовов. Тесты используют временные синтетические базы; настоящий `.env` не читают.

## 3. Настройки

Откройте локальную `.env`. Если переменная уже задана в Windows, она имеет приоритет над файлом.

| Переменная | Что указать |
|---|---|
| `BOT_TOKEN` | Новый токен BotFather, только локально |
| `BOT_USERNAME` | Публичное имя собственного бота без `@` |
| `ADMIN_IDS` | Числовые личные Telegram ID доверенных администраторов через запятую; username не подходит |
| `SANDBOX` | По умолчанию `true`: все исходящие сообщения, фото и предпросмотр сохраняются в SQLite без отправки |
| `ENABLE_TELEGRAM_POLLING` | `false` по умолчанию. `true` разрешает сетевую инициализацию, чтение обновлений и проверку отсутствия webhook |
| `ALLOW_REAL_SENDS` | `false` по умолчанию. Отдельное разрешение реальных ответов и подтверждённых рассылок |
| `NOTICES_APPROVED` | `true` только после утверждения документов владельцем |
| `DATABASE_PATH` | Локальная база, для sandbox и настоящей работы **разные файлы** |
| `BACKUP_DIR` | Защищённая папка копий |
| `MENU_URL`, `DELIVERY_URL` | Настоящие HTTPS-ссылки; проверьте их на телефоне |
| `ACTIONS_URL` | Ссылка именно на актуальные акции. Поле оставлено пустым: бот честно сообщит, что раздел не подключён |
| `CONTACTS_TEXT` | Адрес, часы работы и другие утверждённые контакты |
| `PD_TEXT`, `PD_VERSION` | Утверждённый текст обработки данных и его версия |
| `MARKETING_TEXT`, `MARKETING_VERSION` | Отдельный добровольный рекламный текст и его версия |

Владелец должен утвердить оператора/контакты для обращений, цели, срок хранения, удаление, порядок обработки резервных копий. Черновики из примера не являются готовыми юридическими документами. При изменении текста задавайте новую версию: повторное использование версии с другим текстом блокируется. Тексты каждого согласия сохраняются целиком. Поля `PD_TEXT` и `MARKETING_TEXT` предназначены для короткого понятного текста; соблюдайте общий лимит Telegram в 4096 символов для `/privacy`.

Telegram ID также является персональными данными. Имена, телефоны и даты рождения эта версия не собирает, поскольку они не нужны в текущем ТЗ. SQLite содержит ID, метки источников, согласия, историю, черновики, результаты и журнал администратора. Не кладите базу и копии в Git, общие публичные папки или открытое облако. На Windows ограничьте доступ к папке через «Свойства → Безопасность»; используйте отдельную учётную запись и шифрование диска. В Linux новые файлы создаются с ограниченными правами. Шифрование самой SQLite не реализовано.

### Как узнать собственный Telegram ID

После отдельного разрешения сетевой проверки, **до запуска основного бота**:

1. Внесите новый токен в `.env`, установите только `ENABLE_TELEGRAM_POLLING=true`; оставьте `SANDBOX=true` и `ALLOW_REAL_SENDS=false`.
2. Отправьте своему боту `/start` с личного аккаунта; ответ пока не требуется.
3. Выполните локально:

```powershell
.\.venv\Scripts\python.exe -m restaurant_bot.admin_id
```

Команда делает getMe/getWebhookInfo/getUpdates, выводит только числовые ID личных чатов, без токена, сообщений и имён. Она не отправляет сообщения, не меняет webhook и не передаёт offset для сброса очереди. Добавляйте только свой проверенный ID; при неоднозначности сначала остановитесь и разберитесь. Не запускайте одновременно с другим poller. При существующем webhook команда откажется работать: не отключайте старую систему вслепую. После проверки снова можно выключить сетевой флаг.

## 4. Закрытый ручной тест и запуск

В sandbox не будет ответов даже в Telegram — их имитации хранятся в таблице `messages`, `status='sandbox'`. Полный сценарий без внешней сети проверяют тесты. Для интерактивной проверки в Telegram уже нужны **реальные ответы**, поэтому сначала отдельно согласуйте их.

Для проверки только владельцем используйте нового тестового бота либо не распространяйте ссылку рабочего бота до приёмки. Эта версия не содержит отдельного списка разрешённых гостей: при включении реального режима отвечает любому пользователю личного чата.

После согласования и утверждения документов:

```dotenv
SANDBOX=false
ENABLE_TELEGRAM_POLLING=true
ALLOW_REAL_SENDS=true
NOTICES_APPROVED=true
DATABASE_PATH=data/restaurant-live.sqlite3
```

Вставьте утверждённые версии вместо `draft-*`, заполните токен и ID. Не переключайте sandbox-базу в live: программа откажется, чтобы тестовые гости и очереди не стали реальными получателями.

```powershell
.\.venv\Scripts\python.exe bot.py
```

Остановка — **Ctrl+C**. Только один экземпляр с данным токеном. Файловая блокировка защищает одну локальную базу, но не второй компьютер/другой DATABASE_PATH. Если webhook уже существует, бот завершится без его удаления. Для long polling нужно отдельно согласованно отключить прежнюю webhook-систему; здесь нет команды автоматического удаления.

Проверьте `/start` → отдельное согласие на обработку → добровольное согласие/отказ от рекламы → главное меню. Повторный `/start` не создаёт дубликат и не подписывает повторно. Полезные команды:

- `/help`, `/profile`, `/privacy` — информация и статус.
- `/subscribe` — новое явное рекламное согласие.
- `/unsubscribe` или `/stop` — отказ от рекламы.
- `/delete_me` → подтверждение — удаление профиля, согласий и истории из рабочей базы, остановка будущих отправок. Удаление не стирает старые резервные копии автоматически; применяйте утверждённые сроки хранения.

## 5. Акции и администрирование

В личном чате бота выполните `/admin` с разрешённого ID:

1. «Создать сообщение» → отправьте один текст либо **одно фото с подписью**. Альбомы не поддерживаются; фото передаётся как Telegram file_id, не скачивается на компьютер.
2. Бот покажет предпросмотр только автору и количество текущих подписчиков. В sandbox предпросмотр записывается в базу.
3. «Подтвердить массовую отправку» — отдельное явное подтверждение. До нажатия рассылки нет. Повторное нажатие не создаёт новую отправку. Проверяются ID администратора, автор черновика и одноразовое подтверждение.
4. «Отменить кампанию» — отменяет оставшуюся очередь. Принятые Telegram сообщения отозвать нельзя.
5. «Статистика» / «История» — количество гостей, рекламных подписчиков и результаты. Идентификаторы клиентов в чат администратора не выгружаются.

В аудит пишутся открытие управления, просмотр статистики/истории, создание, предпросмотр, подтверждение и отмена кампании. Доступ задаётся только `ADMIN_IDS`; изменение списка требует перезапуска. Кампании исключённого администратора не продолжаются. Для первого теста подпишитесь только своим аккаунтом и подтвердите акцию с одним получателем.

Последнее маркетинговое согласие проверяется при выборе аудитории и непосредственно перед каждой попыткой доставки. Отписки во время ожидания учитываются. Нельзя отозвать запрос, уже находящийся в Telegram API.

Статусы: `pending` — очередь; `sending` — запрос начат; `sent` — Telegram принял (не прочитал); `sandbox` — только имитация; `skipped` — пропуск; `failed` — известная ошибка; `uncertain` — неизвестен исход запроса. Скорость консервативная: не более примерно16 запросов/сек и одного сообщения в чат за1,1сек. 429 повторяется ограниченно с учётом retry_after; долгое ожидание завершается `failed`, чтобы не блокировать управление. Timeout/сбой сети не повторяется автоматически, потому что Telegram мог уже принять сообщение. После падения процесса `sending` становится `uncertain`. Не перезапускайте кампанию целиком ради одного такого результата.

Из «Истории» можно снова открыть предпросмотр своего черновика. Черновики, аудит, аудитория и статусы сохраняются при перезапуске; незаконченный ввод и кнопки согласий — только в памяти. Если кнопка устарела, выполните `/start` или `/subscribe`. Рассылка по расписанию, бонусная CRM, веб-панель и SMS в это ТЗ не входят и здесь не добавлены.

## Оформление и приветствие

Готовые тексты, настройка `WELCOME_TITLE`/`WELCOME_TEXT` и картинки `WELCOME_PHOTO`, аватара и описания через BotFather, а также обновление работающего бота без замены `.env` описаны в [инструкции оформления](docs/BOT_APPEARANCE_RU.md). Цвет кнопок зависит от темы Telegram гостя.

## 6. Рекламные ссылки и QR

Укажите настоящий `BOT_USERNAME`. Создайте ссылку без обращения к Telegram:

```powershell
.\.venv\Scripts\python.exe -m restaurant_bot.links qr_table_01
```

Результат: `https://t.me/<ваш_бот>?start=qr_table_01`. Закодируйте **этот же адрес** в QR-код. Для разных столов/листовок используйте разные метки. Допустимы латинские буквы, цифры, `_`, `-`, до64 символов; не помещайте в метки телефоны или имена. Сами QR-картинки программа не создаёт. Первый и последний источники сохраняются после согласия, рекламная подписка из ссылки автоматически не возникает.

## 7. Резервная копия и восстановление

Создать согласованную копию, в том числе при работающем боте:

```powershell
.\.venv\Scripts\python.exe -m restaurant_bot.backup backup
```

Используется SQLite backup API, учитывающий WAL; не копируйте только `.sqlite3` вручную при работающем процессе. Команда проверяет целостность и отказывается перезаписывать файл. Копии содержат персональные данные **в открытом виде**, храните их на защищённом/зашифрованном носителе отдельно от компьютера, с утверждённым сроком удаления. Токен в резервную копию базы не входит. Фото сохраняются как file_id, не как независимый архив оригиналов.

Для ежедневной копии создайте в «Планировщике заданий Windows» задачу: программа — полный путь к `.venv\Scripts\python.exe`; аргументы — `-m restaurant_bot.backup backup`; «Рабочая папка» — папка проекта. Учётная запись должна иметь доступ только к нужным файлам. Планировщик здесь автоматически не настраивается.

Восстановление **только в новый файл**, никогда поверх действующей базы:

```powershell
.\.venv\Scripts\python.exe -m restaurant_bot.backup restore --source backups\ИМЯ-КОПИИ.sqlite3 --destination data\restaurant-restored.sqlite3
```

1. Остановите бот. Проверьте новый файл и его целостность.
2. Очереди из копии изолируются: pending/sending не возобновляются, активные кампании отменяются.
3. Повторно примените удаления и отписки, случившиеся после даты копии. Без этого нельзя включать рекламу.
4. Укажите новый `DATABASE_PATH`, сохранив прежнюю базу для отката. Не меняйте sandbox/live-режим сохранённой базы.

## 8. Обновление

1. Остановите бот Ctrl+C, сделайте проверенную резервную копию.
2. Сохраните локальную `.env` и действующие данные вне обновляемых исходников.
3. Получите согласованную версию через Git либо отдельный архив. Не используйте `git reset --hard`, `git clean` или удаление папок data/backups.
4. Установите зависимости и выполните тесты командами из раздела2.
5. Запустите бот, проверьте свой `/start`, `/unsubscribe`, `/admin` и одну тестовую акцию.

Версия схемы —1. Неизвестная существующая SQLite не преобразуется автоматически. Будущие изменения схемы требуют отдельной миграции и проверки восстановления. Для отката нужны совместимый код и сохранённая база; не запускайте старую программу на новой схеме без проверки.

Нативная Windows и настоящий Telegram ещё требуют ручной приёмки. Автоматические тесты выполнялись на Linux/Python3.12 с замоканным Telegram API. Реальных сообщений, запуска polling и публикации этих изменений разработчик не выполнял.
